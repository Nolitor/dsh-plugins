> Status: active · Applies to: this workspace · Companion: [RULES.md](./RULES.md), [DSH-HARNESS-POLICY.md](./DSH-HARNESS-POLICY.md)

This file exists because the same classes of mistake kept costing a session. Each entry is something
that **actually happened here**, not a hypothetical. The rule column is the standing instruction; if a
change cannot satisfy it, say so before acting, not after.

## 1. Code and activation

| # | What happened | Rule now |
|---|---|---|
| F-1 | `0.6.0`'s `lib/client.js` declared `const inject = ['slots']`, used `ctx.slots` in `apply()`, and exported only `apply`. The entry landed in `failed`, the **whole web shell** stopped mounting, and DSH logged nothing. | **Export the service list.** The loader injects only `module.exports.inject`. Every plugin keeps a contract test that evaluates the served module and asserts every `ctx.<service>` it uses is in the exported `inject`. |
| F-2 | The same failure was called "verified" because a clone boot plus 200s on every route passed. | **A browser boot is the only mount proof for a browser half.** `--dump-config`, a 200 on the bundle and `node --check` all pass with an unloadable client module. |
| F-3 | A client-half failure was invisible because the shell prints bare `failed`. | **Silence is not evidence.** When a verdict carries no detail, read the boot checker (`BZ()` in `assets/index-*.js`) and judge the module statically instead of re-running the boot. |
| F-4 | Same-file patches: a fuzzy multi-line edit merged two table rows into one (runtime-spec §3.4, then the policy changelog). The table rendered wrong and the pipe check was what caught it. | **After any table edit, count pipes per row** (escaped `\|` excluded). Insert rows with a single-line anchor, never by replacing a block that ends in a table row. |
| F-5 | A plan section was inserted at the wrong number because §5.2.6 already existed; the reference written into the policy pointed at the wrong section. | **Check the target section number before writing a cross-reference**, then grep the reference back. |

## 2. Measurement

| # | What happened | Rule now |
|---|---|---|
| F-6 | The revoked `opencode-go` credential was declared **alive** after a `generate/text` returned 200. That request went through the local OpenCode server, which authenticates with the `opencode` OAuth — the key itself was never exercised. Calling the backend with the key returned 401. | **Probe the artifact, not the account path.** A dead credential and a working account produce the same 200 through the server. Send the credential itself (or read its status) before judging it. |
| F-7 | `GET {baseURL}/models` and `opencode models` were briefly treated as an entitlement oracle; both list unusable routes. | **A catalog is not an entitlement.** `opencode models` returns the static 49 including the 12 the backend refuses. |
| F-8 | The entitlement design sent **one real completion per route** (49/press) on an account whose quota counts requests. Found only when the owner asked about the daily limit. | **Ask what the quota counts before designing a probe.** Prefer zero-request signals (provider id, plan) and free evidence from real traffic. |
| F-9 | A curl probe returned `403 error code: 1010` (Cloudflare) and was nearly read as a credential verdict. | **An edge/WAF status is not an application verdict.** Re-probe with the client the product actually uses before concluding anything. |
| F-10 | `cp -a` of a profile broke every plugin link (`node_modules/@scope/*` are **relative** symlinks); the isolated boot then reported "cannot resolve" for all bundles. | **Rebuild links as absolute paths** in any profile copy, and label a run invalid-and-discarded when the copy itself is broken. |
| F-17 | A dropped upstream SSE body (`TypeError: terminated`) was reported as `{kind:'error', code:'OPENCODE_BACKEND'}`, so a step that had already produced usable work was discarded — 3 of the last 6 sessions ended that way, and the owner read it as "the turn keeps dying". | **A transport cut is not a request verdict.** Classify the error (`isTransientStreamError`): retry only while nothing has been emitted, otherwise preserve the partial output and close it with a legal `finish` reason. Never invent a finish kind — read the harness's `FinishReasonMap` first. |
| F-18 | 0.7.3-0.7.5 held a tag split *inside an opener* but released a `[tool call …` marker that arrived without its closing `]`, so the notation and its JSON payload were emitted as assistant text and printed on screen. `sanitizeProtocolText` could not catch it because it is per-fragment and its `CALL_MARKER` also requires the closing `]` — the net only ever caught strings that were already intact. The split test in `inline-tags.test.mjs` split **after** `]`, so the suite (229/229 at 0.7.3, **237/237 at 0.7.5**) stayed green while the screen was dirty. | **A partial marker is held, never released.** Any prefix that can still become a marker must be buffered (bounded by `maxHold`) until the shape is decided; only then convert it or strip its syntax. A sanitiser that runs per fragment cannot be the last line of defence for a stream — test the exact delta boundaries recorded from the live stream, not a single-delta blob. |
| F-32 | The rc.5 verification was about to rest on a hand-replayed **A/B probe**. The owner rejected it: a short synthetic prompt makes the model emit almost no reasoning and almost no text, so **nothing can leak** — the defect lives in long, multi-turn, output-heavy turns, and the probe reproduces neither the volume nor the context. Re-running those turns as probes would also spend the owner's quota. The probe was good only as a negative: six header/shape variants on `beam-free` and `deepseek-v4.1-flash` all returned structured `tool_calls` with **0** content markers (a missing `x-opencode-session` returns HTTP 400, so that header is required and already sent), and 0 markers with 38 tools, a long system prompt or a markup-primed history. | **A short probe is not evidence for a streaming defect: the defect needs long, output-heavy turns, and synthetic prompts reproduce neither the volume nor the context. Instrument the real traffic and analyse it instead of buying probe turns.** Record shape (model, message count, context chars, tools, system prompt, token/effort hints) and field/length/marker facts on real requests, with a bounded excerpt only on a marker hit, then aggregate the rate by tool count, context size, system prompt and model — no prompts, no message bodies, no credentials, capped size, explicit kill switch. |

## 3. Live state

| # | What happened | Rule now |
|---|---|---|
| F-11 | A boot-rewritten `profiles/<name>/cordis.yml` was initially blamed on a probe. DSH rewrites that file to a constant on every boot. | **Name the writer before accusing a probe.** Compare content hashes; mtime-only churn on a file DSH owns is expected. |
| F-12 | Raw `GET /api/credential` output was printed once, including `oc_sk_…` key values. | **Credentials: names, ids and lengths only.** Mask every value in tool output, evidence files and docs. |
| F-13 | A credential was almost deleted based on a stale boot-card claim; the deletion then happened only after re-measuring the key itself. | **A deletion is a decision, not a cleanup.** Re-measure the artifact, protect the account-critical entries (`opencode` OAuth / master keys), delete only the named dead one, and verify serving afterwards. |
| F-14 | Settings were written to the live profile while verifying a UI feature (plan toggle). The write was valid but unannounced at the time. | **Announce every live write with its blast radius** in the same reply, or probe in an isolated profile. |

## 4. Reporting

| # | What happened | Rule now |
|---|---|---|
| F-15 | A wrong conclusion (F-6) was already committed to a boot card before it was retracted. | **Correct in the same artifact** with a table of what each measurement path proves; never leave a stale conclusion standing because it is "just a card". |
| F-16 | Numbers were quoted without their unit/derivation ("49 requests" needed the qualifier *per press*, at concurrency 6, one per route). | **A derived number carries its unit and shape**, or it is not reviewable. |
| F-19 | The 0.7.6 docs were committed at 00:10:07 with a **stale index**: `bootcards/2026-11-01T0007+0900.md` was generated *after* the last `npm run docs:index`, so the committed `INDEX.md` still said "52 indexed / 52 documents" and listed the previous card. `npm run docs:check` therefore **failed on the committed tree** — the gate had run before the last write. | **`npm run docs:check` is the last command before a docs commit.** Order: write/edit docs → generate derived files (`bootcard`, `docs:index`) → `docs:check` → commit. A green check from before the last write proves nothing. |

## 5. Live service and provider wiring

| # | What happened | Rule now |
|---|---|---|
| F-20 | The 3080 service was replaced by `fuser -k 3080/tcp` — SIGKILL by default. The unit (`Type=simple`, `KillMode=control-group`, `Restart=always`, `RestartSec=3`) has no drain, so the in-flight agent turn died with no record, and the restart was reported to nobody. Measured: `Main process exited, code=killed, status=9/KILL` at 00:12:38, **no systemd `Stopping` line** (real stops do log one, e.g. 23:11:14 / 23:33:13 / 23:40:29), no kernel OOM, `MemoryMax=infinity`, restart at 00:12:41. | **Stop the unit, never the port holder.** Use `systemctl --user restart`/`stop` so systemd owns the shutdown, and report the restart with its before/after facts in the same reply. A SIGKILL of the listener is indistinguishable from a crash in the journal and loses whatever the turn was doing. |
| F-21 | A turn died with `opencode GET /api/provider/opencode-go -> HTTP 404: ProviderNotFoundError`. Cause: `lib/http.js` defaults `backendProviderId` to `opencode-go` and resolves the backend with `GET /api/provider/{id}` when no explicit base URL is set — but the local control plane's auth catalog is `opencode`, `opencode-zen`, `zen`; there is no `opencode-go` provider. | **Resolve a provider id from the live catalog before issuing it.** A default id is a guess; read `/api/provider` (or `auth.json` keys), match it, and on a 404 fall back to a known id instead of failing the turn. |

## 6. Stream typing at the boundary

| # | What happened | Rule now |
|---|---|---|
| F-22 | The 0.7.3-0.7.8 stream fix was built as a **downstream text scanner**: lib/inline-tags.js plus lib/stream-parser.js grew six tag families and re-typed delta.content by pattern. Every new defect (split marker, stray closer, multi-call blob, malformed JSON) was answered by another pattern. Measured on 29,940 recorded deltas: 1.7% carried notation, 37.6% were plain prose, and all 11,061 reasoning deltas were re-sanitised fragment by fragment. | **A part's type comes from the wire field, never from its characters.** Map delta.reasoning_content to reasoning, delta.tool_calls to tool-call, delta.content to text at the boundary (lib/upstream-map.js), and let the downstream reducer forward typed parts unchanged. If a route leaks notation into content that is the route's defect to fix or a renderer's to display; adding one more tag to the scanner is forbidden (0.8.0, dsh-opencode-v2/VERIFICATION.md section 37). |
| F-23 | A live-stream switch was nearly reported as done from beacon lines alone: "0.8.0" had appeared in /tmp/opencode-v2-boot.jsonl while the serving pid still logged 0.7.5 with router:true. Those 0.8.0 lines were the **test suite** (17 streaming tests per run), not the service. Only the pid, the ExecMainPID and a field that exists in exactly one build settle it. | **Identify the process, not the version string.** Before claiming a live code switch, report the serving pid before and after, a field present in only one build, and the timestamp of the last old-code write. A version string in a log is not a mount proof. |
| F-24 | The display-cleaning round was first "verified" with hand-written fixtures plus a metric that only described itself: `held = delta.length - emit.length` summed over one unflushed trace produced "33,921 / 99.835% held", which is a per-push deferral, not delay — the gate actually holds at most 11 characters of reasoning and nothing of prose. The owner rejected it ("실제 모델 찔러서 테스트해"). | **Measure the thing the user experiences, on a real model, through the real transport.** Latency is first-delta time and inter-delta gaps versus the previous build; correctness is pass rate over real runs plus a replay of real recorded traffic. A metric you cannot explain to a reviewer in one sentence is not a measurement. |
| F-25 | `VERIFICATION.md` shipped two byte-identical copies of round 37; the duplicate survived the 0.8.0 release commit and was only found during the 0.9.0 doc cleanup. | **Before a version bump, count the round headings.** `grep -c '^## <n>\\.'` must be 1 for every round; a duplicated block hides stale claims and doubles the document. |
| F-26 | The 0.9.0 release was committed and packed while `lib/http.js` still had `const VERSION = '0.8.0'` — the load beacon would have labelled the new build as the old one after the restart, and the released tarball carried the wrong string. It was caught only during the pre-restart re-read of the module. | **A version constant outside package.json is part of the release.** After a bump, `grep -rn "'<old-version>'" lib/ bin/` and re-pack/re-hash; the beacon must name the build it belongs to. |
| F-27 | 0.8.0 deleted the owner's state machine without instruction; 0.9.0 answered the leak with a display-only filter that mutates the single text stream, so the parser channel and the screen channel could not be separated and live notation kept leaking (measured: 20 of 65 messages in the first 90 minutes of 0.9.0). The 26 self-bumped versions (0.1.1 to 0.9.0) came from the same habit: treating a release as permission to move the number. | **The owner's architecture is not yours to simplify.** The top classifier and the bottom parser/screen gate are separate requirements; a filter is not a gate. Version bumps happen only on instruction, and then only as `0.0.1.rc<N>`. |
| F-28 | The adapter appended tool-argument fragments from the route, assuming a fragment contract the route does not honour: it **re-sends the whole arguments object** as a second delta, so the host received concatenated JSON (`{"code":…}{"code":…}`) and reported `ToolArgsError INVALID_ARGS` (`"arguments" must be an object`) — the turn was lost. Measured session `2dc3531f`: 80 tool calls, **30** failed; 24 second copies were exact duplicates, 6 restated with changed content, 3 arrived wrapped as `{"arguments":"<json>"}`. The same session showed the second half: a harness that recognizes only **marked** notation displays a bare JSON call typed into `content` as prose (4 occurrences), so the call is read by the user and never executed. Corpus re-measurement (267 sessions, 16,709 calls): 44 -> 0 invalid after normalization. | **Accumulate wire fragments defensively: a re-sent full snapshot is not a fragment. Decide the final arguments against the declared schema before the host sees them, and treat a body payload that is only a tool-shaped JSON object as a call (promote or drop), never as prose.** |
| F-29 | 0.0.1-rc.1's top classifier recognized tool-call markers from a **hard-coded list of literal openers**, so when the route started writing a new corrupted family it matched none of them: `<tool_call #call_00_…>`, `<tool call run_code #code_placeholder_001>`, closer-shaped parameter openers `</│DSML│ parameter name="code">…</│DSML│>`, doubled pipes `</｜｜DSML｜｜ parameter>`, a bare `</│DSML│>`, `<│DSML│parameter name="description">…</│DSML│>`, and mixed `<tool call run_code #id]: {json}`. Replay through rc.1: **0 calls promoted, 0 characters removed** — the marker was printed verbatim and the intended call never executed, which the owner experienced as a "forcibly cut" turn. Measured across all `opencode-route` sessions: strict screen leaks 301 -> 4, loose mentions 333 -> 49, calls promoted 24, duplicate restatements dropped 209. | **Classify by shape, not by a literal whitelist: bracket style, name/id position and pipe glyphs vary. If the head cannot name the tool, infer it from the declared parameter schema. Never let a marker reach the screen, and de-duplicate by call id.** |
| F-30 | 0.0.1-rc.2's classifier was exercised only on **whole payloads**. A real SSE stream splits the marker: `<tool ca` was printed as prose before recognition and the remainder no longer sat at a line start, so turn 16 of session `2dc3531f` still showed the notation on **3 of 6** assistant messages (steps 3, 4, 6 printed `<tool call run_code #call_00_…]: {json}`; step 8 printed a bare code body after its `<parameter name="code">` opener was lost). Replaying the same text as one string leaked **0**; one character at a time leaked **4 of 6**. Measured worst-case chunking across 3,689 assistant messages: strict screen leaks **42 -> 3**, calls promoted from body payloads **28**, turn 16 **4/6 -> 0/6**. | **Feed every recogniser one character at a time in tests. A marker may be split anywhere: hold a bounded prefix that can still become one, and never print a partial token.** |
| F-31 | 0.0.1-rc.3's scrub recognised only the DSML token (`｜DSML｜`) and the think/thinking/analysis wrappers. After the restart onto rc.3 (serving `pid 2339788`, 09:42:39 KST) nine turns (17-25) had **0 tool errors** but two messages still printed protocol tokens that are **not DSML**: turn 18 step 6 `<｜End of thought｜>`, turn 20 step 3 `<｜thought>` and `</thought>`. The model had moved to another token in the same delimiter family; an enumerated token list cannot cover it. | **Strip by delimiter shape (any `<｜…｜>` token), and treat every thought/think/analysis spelling as a reasoning wrapper.** Recognise families by their delimiter, never by the token text; a split token must be held until its shape is decided. |

## 7. Using this file

- Before changing a plugin: read §1. Before measuring: §2. Before touching `~/.dsh`: §3.
- When a new mistake is made, add it here **with the rule**, not with a narrative. The rule is the
  artifact; the incident is only the reason for it.

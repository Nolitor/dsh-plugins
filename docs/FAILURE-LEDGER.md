# Failure Ledger — Mistakes Made Here, and the Rule That Prevents a Repeat

> **2026-11-04 — staged package shipped as a plugin, and a green suite stood in for a soak.**
> `@nolit/dsh-opencode-v2-beta` was created to stage a better protocol parser, but it
> registered the same tool, commands, worker and model route as the stable package (so only
> one could ever be active) and shipped no `locale`, so its plugin card rendered as the bare
> specifier next to `Opencode v2 Agent`. Separately, `0.0.2` was released on a green suite
> alone and failed its first live boot (`ctx.tools` without `inject` → "1 entry did not
> activate"). **Rule:** a staged change is source under `staging/`, never an installable
> package; and a release needs the `S6` soak, measured by
> `scripts/opencode-v2-stabilisation-status.sh`, not by a passing suite. See
> [dsh-opencode-v2/docs/OPENCODE-V2-STAGE-PLAN.md](../archive/dsh-opencode-v2/docs/OPENCODE-V2-STAGE-PLAN.md).
> **Second, related:** the cost pill was gated on a MODEL id prefix, so other routers serving
> `opencode-go/*` showed it. **Rule:** ownership is the provider id the package registers,
> never a model name it does not control.

## 1. Code and activation

That looked like the fix for the earlier `MISSING_CREDENTIAL` failures, but the profile still produced `ACCOUNT_SIGN_IN_REQUIRED` **every ~10 s**: 24 consecutive failures 07:13-07:23 on 2026-11-02, and 413 overhead ledger records where the judge ran but `spiral_nudge_writer_tokens` was `0` in **every** one, because the call never returned text. The cause is that `@deepseek-ai/dsh-headless` disables `credentials`, `authorization` and `deepseek-account` ('one-shot jobs use launch-time credentials'), so `deepseek-account`'s `resolveToken()` never had a store to read. A config row pointing at a provider is not a mounted provider. | **A route is only as mounted as its dependencies.** After pointing a profile at a provider, prove it with a real call, and read the dependency chain (here `deepseek-account` -> `authorization` -> `credentials`) instead of assuming the bundle leaves them on. Judge by returned text plus ledger effect, not by the absence of an error: identical error text can come from different missing services, so a repeated signature is not proof the same cause is still in play. |
| F-37 | The tiering minimum-size gate was chosen as if the warm summary had a constant size. It does not: the summary is `head (2000) + tail (600) + structural index`, and the index grows with the content (up to 20 file paths, 12 headings, statuses, error counts). Measured floor spans **2,764 chars** on a plain log to **3,517** on a path-dense one, so `minChars: 1200` rewrote outputs *smaller than their own replacement* in 341 of 645 cases (+245,927 chars of self-inflicted context growth). Raising it to 3000 cut that to 1 case; **3700** removed the last one. A fixed input-size floor is a bound on the input, never on the output. | **When a transform's output size depends on content, the gate must be derived from the measured maximum of the offending class, not from a round number or an assumed constant.** Re-measure the `after > before` population every time the transform changes, and state the residual explicitly: a floor bounds inputs, so content denser than the sample can still inflate. Prefer the structural invariant (`refuse when output >= input`) over any constant. |

| F-53 | While splitting the documents per subproject, the link rewriter resolved every target to a repo-root path and re-emitted it relative to the file's **new** directory — including files that had not moved. 607 links broke across the boot cards and every track. ## 7. Using this file

- Before changing a plugin: read §1. Before measuring: §2. Before touching `~/.dsh`: §3.
- When a new mistake is made, add it here **with the rule**, not with a narrative. The rule is the
  artifact; the incident is only the reason for it.
| F-57 | Submodule conversion ran as a bash loop using an undefined `$r` in `git submodule add https://github.com/Nolitor/$r`; the three `git rm --cached` + `rm -rf` steps had already executed, so three plugin directories were deleted while the loop added nothing. Recovery came from HEAD (the tree was fully committed moments earlier, verified `git diff HEAD` empty before the operation). | **Never run state-destroying steps in a loop over a variable the loop itself defines later.** Convert one track per command, verify (`git ls-files -s`, package.json version) after each, and only proceed when the previous step measured green. A delete-then-readd recipe must be rehearsed with the variable defined. |
| F-58 | `npm view <pkg> version` was reported as "the published version" while the workspace convention is `--tag rc` for prereleases; `latest` stayed at an old rc and the report claimed npm was behind. The real dist-tags check showed all four packages current. | **Before declaring a version drift, read the dist-tags map, not the default tag.** A prerelease workspace never moves `latest`; `npm view <pkg> version` returns only that. |
| F-59 | Tag SHAs were captured as 10-hex prefixes and then pasted as 40-char strings (invented tail hex) into a tag-creation script, so every `git/refs` POST failed; two tags were subsequently created at the wrong commit by `gh release create` (branch HEAD) and had to be PATCH-retargeted to the version commits. | **A SHA is either the full 40-hex measured from the API or not used at all.** Never extend a truncated hash by hand; after any tag write, verify with the raw ref endpoint (`/git/ref/tags/<name>`), not the CDN-cached listing. |

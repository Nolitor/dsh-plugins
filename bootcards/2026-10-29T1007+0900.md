## 1. Non-negotiable rules

1. **Measure first.** Read actual state; do not trust memory, report text, or a plan.
2. **Sidebar Manager drift gate.** The live plugin may include UTM modifications that differ from
   the packaged release. Before any change/version-up: run `node scripts/audit-installed-vs-packaged.mjs`,
   record tree SHA-256, test the current behavior in an isolated `DSH_HOME`, then version-up.
3. **Isolate live state.** Use a workspace-local `DSH_HOME` for experiments. Do not write
   `~/.dsh`, the live profile, sessions, or the running 3080 service without explicit approval.
4. **Version gate.** Plugin `engines.dsh` must include the running DSH prerelease exactly:
   `>=0.2.2-alpha.2 <0.3.0` for the current generation.
5. **Release artifacts are immutable.** Update `artifacts/SHA256SUMS.*` whenever a package
   changes; never claim a release without a matching hash.
6. **UTM is advisory.** Do not introduce hard write-blocks based on UTM role/policy. Use
   observation, warning, soft rejection, and audit records only.
7. **Notification delivery is deduped.** If Chrome OS notification succeeds, do not also show
   the in-app toast; use toast/title/sound only as fallback.
8. **Locale parity.** Korean dictionaries must match both `en` and `zh` key sets and
   placeholders before release.
9. **Single writer.** Write only inside your assigned `dsh-<track>/`. Never write a sibling
   track via a bare relative path; assert `package.json.name` before replacing a manifest.
10. **Plugin replacement is 4 steps, never one.** disable incumbent row -> remove incumbent
   package -> add new package -> verify by **real mount**. A passing `--dump-config` does NOT
   prove a plugin mounts; two plugins registering the same tool/route is a hard mount failure.

## 8. INCIDENT — live profile corrupted by a scope-glob symlink (repaired this session)

**Symptom.** `dsh --profile web` failed to boot with
`ELOOP: too many symbolic links encountered, realpath '…/profiles/web/node_modules/@agentclientprotocol/*'`.
The running 3080 service survived only because it had booted before the damage.

**Cause.** A sandbox script (`/tmp/ocv2-verify/mk-iso2.sh`) built the isolated profile by
`mkdir -p "$PROF/node_modules/$s"` over a **symlinked** scope directory, then globbed
`for c in "$sc"/*`. When the source scope dir was empty, the unexpanded glob `*` became a
symlink **inside the live profile**, pointing at its own directory. It self-amplified: the next
run globbed that `*` again. Affected: `@agentclientprotocol/*`, `@hono/*`,
`@modelcontextprotocol/*`, and `@standard-schema/spec/spec`.

**Repair (applied).** Removed the four bogus symlinks. The live profile then booted clean, and
`dsh --profile web --dump-config` printed the composed tree with **no** warnings. The stale
`dsh-plugin-opencode` / `dsh-plugin-opencode-provider` rows in the profile patch (upstream bundle
no longer selected) were repointed to `dsh-opencode-v2` / `dsh-opencode-v2-provider`.

**Real mount verified** (not just `--dump-config`): the plugin inventory reports
`include:dsh-opencode-v2` and `include:dsh-opencode-v2-provider` with `fiberPhase: active`,
`failed` entries = 0.

**Rule for future sandbox scripts.** Never `mkdir -p` / `ln -sfn` through a symlinked directory
that points outside the sandbox. Copy real directories, or link the *scope dir* itself and write
only into a fresh local directory. A glob over an empty directory yields the literal `*`.

### 8.1 v2 `step_finish` correction

The 0919/0946 cards and `OPENCODE-V2-SURFACE-MEASUREMENT.md` claimed v2 emits **no**
`step_finish`. Re-measured: a **tool-using** run does emit `step_finish`, carrying that step's
`tokens` (`input`/`output`/`reasoning`/`cache.read`/`cache.write`) — e.g.
`{input: 55, output: 19, reasoning: 38, cache: {read: 5056, write: 0}}`. It is a **per-step**
total, never a whole-run one, so `session export` remains the only authoritative usage source and
the plugin's fallback path is unchanged. All affected docs corrected.

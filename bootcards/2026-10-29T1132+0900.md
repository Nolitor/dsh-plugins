## 1. Non-negotiable rules

1. **Measure first.** Read actual state; do not trust memory, report text, or a plan.
2. **Sidebar Manager drift gate.** The live plugin may include UTM modifications that differ from
   the packaged release. Before any change/version-up: run `node scripts/audit-installed-vs-packaged.mjs`,
   record tree SHA-256, test the current behavior in an isolated `DSH_HOME`, then version-up.
3. **Isolate live state.** Use a workspace-local `DSH_HOME` for experiments. Do not write
   `~/.dsh`, the live profile, sessions, or the running 3080 service without explicit approval.
4. **Version gate.** Plugin `engines.dsh` must include the running DSH prerelease exactly:
   `>=0.2.2-alpha.2 <0.3.0` for the current generation.
5. **Release artifacts are immutable.** Update `artifacts/SHA256SUMS.*` whenever a package
   changes; never claim a release without a matching hash.
6. **UTM is advisory.** Do not introduce hard write-blocks based on UTM role/policy. Use
   observation, warning, soft rejection, and audit records only.
7. **Notification delivery is deduped.** If Chrome OS notification succeeds, do not also show
   the in-app toast; use toast/title/sound only as fallback.
8. **Locale parity.** Korean dictionaries must match both `en` and `zh` key sets and
   placeholders before release.
9. **Single writer.** Write only inside your assigned `dsh-<track>/`. Never write a sibling
   track via a bare relative path; assert `package.json.name` before replacing a manifest.
10. **Plugin replacement is 4 steps, never one.** disable incumbent row -> remove incumbent
   package -> add new package -> verify by **real mount**. A passing `--dump-config` does NOT
   prove a plugin mounts; two plugins registering the same tool/route is a hard mount failure.

## 7. DSH parent + DeepSeek API capability re-measurement — usage / cluster / cache

### 7.1 Question

Re-measure whether **usage**, a **cluster host controller**, and **cache nesting** can be added,
using either the DSH parent framework or what the DeepSeek API provides — and whether they can be
done **together**.

### 7.2 Answer (measured)

**Yes to both.** All three can be added, and they fit in **one plugin**. A throwaway probe plugin
mounted once in an isolated `DSH_HOME` (`/tmp/opencode/iso`) and reached every seam it needed.

| Feature | Verdict | Decisive measurement |
|---|---|---|
| Usage | **addable**; balances and token/cache counters **already ship** in the product | The one gap is `total_costs` (cumulative spend), which the Platform returns and the shipped adapter drops |
| Cluster host controller | **addable, but new** — DSH has **no** cluster concept | The plugin spawned **two** `dsh --profile sdk` children and completed `initialize` on both over stdio JSON-RPC |
| Cache nesting | **addable**; must be pinned to one meaning first | The plugin observed real provider cache hits: `cacheReadTokens` 0 → **128** → **128** over three identical-prefix calls |

### 7.3 Key measured facts

- **`total_costs` is dropped by the shipped schema.**
  `packages/credentials/deepseek-account-platform/src/details.ts:17` parses only `normal_wallets`
  and `bonus_wallets`; the Platform's `get_user_summary` also returns `total_costs` (live: USD
  36.6436414340000000, CNY 6.1283399200000000).
- **DSH has no cluster/host-registry concept.** `hostId` → 0 hits; `multi-host` → 1 hit and it is
  a *negative* statement in `dsh-experimental-liveshare/README.md:162`; `cluster` → 8 hits, all
  metaphorical (Client Session object layer, Unicode grapheme clusters, stream-tail verb,
  Chrome DevTools metrics). "Remote" in DSH means *typed Client↔Host RPC*, not a remote machine.
- **DeepSeek's platform API exposes no host/cluster endpoint** — `/api/v0/hosts`, `/api/v0/nodes`,
  `/api/v0/cluster`, … all 404.
- **DeepSeek context caching is on by default and already reported by DSH.** Live Anthropic-route
  usage: `cache_read_input_tokens` 128 → 256 → 256 on identical prefixes. DSH maps it to
  `cacheReadTokens`/`cacheWriteTokens`
  (`packages/llm/llm-deepseek/src/translate.ts:36`).
- **There is no nested/hierarchical cache in DSH.** Grep for `hierarchical cache`, `nested cache`,
  `multi-level`, `tiered`, `L1`/`L2` → 0 hits. Every cache is single-level.
- **A plugin can own a Host HTTP route** — `ctx.webServer.register({ kind:'exact', path, handler })`
  served `{"spend":[…]}` with HTTP 200. Note `dsh-host-webserver` has **no** server-wide auth, so
  a plugin publishing spend must authorize it itself.

### 7.5 Service-injection facts worth keeping

Cost real debugging time in the probe and will cost it again:

- `ctx.get(<service>)` returns **`undefined`** unless the plugin declares a matching
  `export const inject = ['<service>']`. The effect then runs before the service activates.
- `ctx.on('llm/stream', …)` **pends** without `inject = ['llm']`.
- Both look like "the feature is unavailable" and are actually "no dependency declared".

## 3. M10 UI sprint — next session, top priority (owner-defined)

The backend is wired but the front end is broken in three ways; fix all three under one
"커스텀 라우터" entry.

1. **Metadata & i18n** — the package name must not leak into the UI. Ship display names
   `커스텀 라우터` / `Custom Router` (and zh) plus per-locale description dictionaries.
2. **Missing switches** — per-preset enable toggles for antigravity / opencode / deepinfra, and
   per-preset sub-layer switches (**model router / subagent / CLI worker**) rendered from a
   schema-driven settings UI.
3. **Missing preset dashboard** — one plugin main "preset settings" page (dashboard), not just
   per-field rows.
4. **Zombie vendor tabs** — no separately exposed vendor tabs in the settings menu; one
   consolidated "커스텀 라우터" entry. (The vendor client bundles are already removed from the
   profile; if a tab still renders, it is a stale client bundle/cache, not a live row.)

Measured starting points:

- `dsh-custom-router/package.json` has **no `dsh.client`** entry and no client bundle → nothing
  renders today. Reference implementations: `dsh-antigravity` (settings section + usage chip),
  `dsh-opencode-v2`, `dsh-notify` (settings + locale).
- `lib/index.js` exports **no `Config` schema** (auditor finding #4) → the settings service
  cannot project fields and edits would cause full remounts. Adding the schema is part of M10.
- Switch data already exists: `presets.antigravity|deepinfra|opencode` booleans in the row config;
  sub-layer switch declarations in `lib/presets.js` (`switches[]`: `enabled` / `modelServing` /
  `subagent` / `cli` / `workerEnabled` per preset).
- `vendorConfig` carries secrets (DeepInfra key) — the settings UI must **not** expose them; it
  edits switches and model lists only.
- i18n pattern: `locale/en.json` + `locale/ko.json` + `dsh.client.inject` of
  `@deepseek-ai/dsh-client-locale`.

Exit criteria for M10: settings page renders under the single "커스텀 라우터" entry with the
localized name/description, per-preset + sub-layer toggles that persist through the settings
service and take effect on the running router, dashboard page, zero vendor tabs, client tests,
and a real-mount verification (UI + `verify-mount` still PASS).

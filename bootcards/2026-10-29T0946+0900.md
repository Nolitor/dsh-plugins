## 1. Non-negotiable rules

1. **Measure first.** Read actual state; do not trust memory, report text, or a plan.
2. **Sidebar Manager drift gate.** The live plugin may include UTM modifications that differ from
   the packaged release. Before any change/version-up: run `node scripts/audit-installed-vs-packaged.mjs`,
   record tree SHA-256, test the current behavior in an isolated `DSH_HOME`, then version-up.
3. **Isolate live state.** Use a workspace-local `DSH_HOME` for experiments. Do not write
   `~/.dsh`, the live profile, sessions, or the running 3080 service without explicit approval.
4. **Version gate.** Plugin `engines.dsh` must include the running DSH prerelease exactly:
   `>=0.2.2-alpha.2 <0.3.0` for the current generation.
5. **Release artifacts are immutable.** Update `artifacts/SHA256SUMS.*` whenever a package
   changes; never claim a release without a matching hash.
6. **UTM is advisory.** Do not introduce hard write-blocks based on UTM role/policy. Use
   observation, warning, soft rejection, and audit records only.
7. **Notification delivery is deduped.** If Chrome OS notification succeeds, do not also show
   the in-app toast; use toast/title/sound only as fallback.
8. **Locale parity.** Korean dictionaries must match both `en` and `zh` key sets and
   placeholders before release.

### 7.1 What the 0919 card got wrong (measured)
- The sandbox **no longer** blocks `~/.dsh`: this shell is a plain ext4 rw mount.
- `opencode-go/*` routes **do work** with the real `HOME`. The reported `provider.no-route` came
  from a fake `HOME` with no `auth.json`. Catalog = **45 models** (30 `opencode-go/*`, 15 `opencode/*`).
- Upstream does **not** pass `--attach`/`--pure` unconditionally — only when truthy.
  (`--pure` / `--attach` on v2 = `Unrecognized flag`, exit 1, usage text on **stdout**.)
- Partly true: v2 sends **no whole-run** `step_finish`. A tool-free run emits no `step_finish` at all;
  a tool-using run emits a **per-step** `step_finish` with that step's `tokens`. Neither is a whole-run
  total, so tokens come from `opencode session export <sid>`.

### 7.4 Three traps for the next session
1. **`--dump-config` exit 0 does NOT prove a plugin mounts.** It never imports, registers, or
   runs startup audits. A config with BOTH `@quonaro` rows and v2 rows dumps cleanly and then
   fails to mount: `tool "opencode" is already registered` + adapter `"opencode-agent"` already
   registered. **A real mount is the only valid gate.**
2. **The `@quonaro/dsh-plugin-opencode` rows must be disabled/removed in `web` before enabling
   v2** — both register a tool named `opencode` and the route `opencode-agent`.
3. **Port 49374.** A stale `opencode serve --service` from a *different* `HOME` squats it and
   every command fails with `Managed service port 49374 … already in use`. A second
   `serve --service` on the same port exits **0 silently**, so a no-op proves nothing. Remedy:
   `opencode service set port <port>`; only kill after checking `/proc/<pid>/environ` HOME.
   The user's real service runs on 49374 — earlier this session a leftover `/tmp/oc2` service
   from an abandoned experiment had to be killed.

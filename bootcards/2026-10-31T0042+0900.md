## 0.1 U1 closed — the revoked opencode-go key was deleted (after one wrong reading)

Card `2026-10-30T2330+0900` U1 said the `opencode-go` credential (`cred_1830…`, `…4yjF`) was revoked
with **401 Invalid credential**. Two measurements disagreed, and the second one is the correct one:

| Path measured | Result | What it proves |
|---|---|---|
| `POST /api/experimental/generate/text` via the local OpenCode server | **200** | the *account* serves models — the server authenticates with the `opencode`/`Personal` oauth, not with the go key |
| `POST {provider.settings.baseURL}/chat/completions` with **that key** as `Bearer`, `max_tokens: 4` | **401** `Upstream request failed: Invalid credential` | the go **key itself is dead** — U1 was right |

The first reading was reported as "the key is alive"; that was wrong — it exercised the oauth path.
`@nolit/dsh-opencode-v2` prefers oauth over key (`activeCredential()` ranks `oauth` 0, `key` 1), so
the dead key was never in use.

Deletion (owner-approved) executed 2026-10-31 00:47 KST: `DELETE /api/credential/<go key>` → 204.
Store afterwards: `Master Key 1`, `Master Key 2` (inactive, untouched) and `Personal` (oauth, active,
untouched — this is the DSH web auth). Serving re-verified after the delete: `generate/text` → 200,
`dsh-web.service` active.

## 5.1 Sweep cost — what one button press actually sends

| Property | Value (measured from `measureEntitlement()`, http.js) |
|---|---|
| Requests | **1 POST per catalog route** → 49 today, to `provider.settings.baseURL` (`https://opencode.ai/inference/go/openai/v1/chat/completions`), bypassing the local server |
| Body | `{messages:[{role:'user',content:'x'}], max_tokens: 4, stream: false}` + `x-opencode-session: dsh-entitlement-sweep` |
| Concurrency | 6 workers, single pass, ~20 s |
| Retry | only when the error text mentions a minimum token floor, then one more request at `max_tokens: 16` |
| Classification | 2xx `usable`; `deprecated` / `unavailable` by message text; 401 `auth`; 403 `forbidden`; **everything else `error`** |

- The 49-route run produced 35 `usable`, so those routes accept `max_tokens: 4` — no floor retries in
  that run. The 12 `unavailable` + 2 `deprecated` are backend rejections, not retries.
- **Gap:** a `429` lands in `error` (indistinguishable from a broken route) and is persisted as a
  verdict. A rate-limit hit would silently look like "this route is broken".
- **Quota:** `/api/experimental/usage/limits` exposes only rolling / weekly / monthly **percent**
  (1% steps, no request counter). Three probe requests moved nothing (2→2, 42→42, 22→22), so this
  endpoint cannot answer "how many requests did I use today". The account console
  (`…/activity/overview`) is login-walled; it was not opened.
- **Practical cost if the limit is per-request:** one press = 49 requests (up to 98 with floor
  retries). Tokens are negligible (≤4 output tokens, ~10 input each). The 00:38 sweep finished
  49/49 with zero rate-limit or error responses, so a 6-way burst was accepted.

## 1. Non-negotiable rules

1. **Measure first.** Read actual state; do not trust memory, report text, or a plan.
2. **Sidebar Manager drift gate.** The live plugin may include UTM modifications that differ from
   the packaged release. Before any change/version-up: run `node scripts/audit-installed-vs-packaged.mjs`,
   record tree SHA-256, test the current behavior in an isolated `DSH_HOME`, then version-up.
3. **Isolate live state.** Use a workspace-local `DSH_HOME` for experiments. Do not write
   `~/.dsh`, the live profile, sessions, or the running 3080 service without explicit approval.
4. **Version gate.** Plugin `engines.dsh` must include the running DSH prerelease exactly:
   `>=0.2.2-alpha.2 <0.3.0` for the current generation.
5. **Release artifacts are immutable.** Update `artifacts/SHA256SUMS.*` whenever a package
   changes; never claim a release without a matching hash.
6. **UTM is advisory.** Do not introduce hard write-blocks based on UTM role/policy. Use
   observation, warning, soft rejection, and audit records only.
7. **Notification delivery is deduped.** If Chrome OS notification succeeds, do not also show
   the in-app toast; use toast/title/sound only as fallback.
8. **Locale parity.** Korean dictionaries must match both `en` and `zh` key sets and
   placeholders before release.
9. **Single writer.** Write only inside your assigned `dsh-<track>/`. Never write a sibling
   track via a bare relative path; assert `package.json.name` before replacing a manifest.
10. **Plugin replacement is 4 steps, never one.** disable incumbent row -> remove incumbent
   package -> add new package -> verify by **real mount**. A passing `--dump-config` does NOT
   prove a plugin mounts; two plugins registering the same tool/route is a hard mount failure.

## 7. opencode-agent reasoning levels (사고력) — v0.1.2

### 7.1 Defect (measured)

The prompt's thinking selector exists only for a model whose **exact** resolution returns
`reasoning`: `buildModelCatalog` (`dsh-api-session-controller/lib/index.js:473-495`) fills
`model.reasoning` from `llm.resolveModelInfo()`, and the client renders effort choices only when it
is present (`dsh-client-ui-model-selection/lib/client.js:1213`). `resolveModel()` returned none, so
OpenCode routes had no level choice, and an explicit level was rejected with
`UNSUPPORTED_REASONING_EFFORT`. `--thinking` was already passed, but it only controls whether
reasoning blocks are streamed — it cannot pick a level.

### 7.2 OpenCode v2.2.0 surface (measured)

| Probe | Result |
|---|---|
| `opencode run --help` | `--model, -m string  Model to use in the format provider/model#variant` |
| `GET /api/model` via `opencode serve` | 45 models, **35 with `variants`** |
| variant ids | `high` 30, `low` 29, `max` 22, `medium` 20, `xhigh` 17, `none` 13, `minimal` 4, `thinking` 1 |
| variant payload | `{ id, settings: { reasoningEffort } }` or `{ id, settings: { thinkingConfig / thinking } }` |
| unknown variant | `{"type":"error","error":{"type":"provider.no-route","message":"Variant unavailable for opencode/deepseek-v4.1-flash-free: bogus"}}` |
| `-m …#low` vs `#high` (same prompt) | both exit 0; reasoning text 46 vs 4 chars — the variant reaches the provider |

### 7.3 Fix

- `shared.js`: `modelFromApiEntry()` keeps `variants`; `reasoningEffortsFromVariants()` maps them to
  host efforts (canonical order, unknown ids kept, duplicates dropped); `withVariant()` composes
  `provider/model#variant`.
- `provider.js`: `resolveModel()` publishes `reasoning` **only** when the route declares variants and
  sets no `defaultEffort` (OpenCode's own default stays in force); `stream()` composes the `-m`
  value from `options.reasoningEffort`.
- Discovery is **single-flight** (`discover()` shares one `discoverOnce()`): the host resolves all 46
  routes when it builds the prompt catalog, so one `opencode serve` covers the whole build.
- The `opencode models` fallback discloses no variants, so it advertises no levels rather than
  inventing them.
- **Discovery defect fixed:** the v0.1.1 probe read `handle.stdout` while spawning serve in
  collect mode; `dsh-subprocess` exposes that stream only for `stdout: 'pipe'`
  (`types.d.ts:159`), so discovery always returned null and every route ran on the 32768 floor
  with no levels. v0.1.2 spawns piped, parses the banner, and bounds the wait.

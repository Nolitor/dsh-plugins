## 1. 기능 설명
DSH 환경의 불필요한 토큰 재전송을 차단하고, 대용량 도구 출력을 계층적으로 압축하여 비용과 대기 시간을 획기적으로 절감합니다.

- **Tiering (고효율)**: Turn 기반의 동적 출력 압축 (Warm/Cold 티어링)
- **Dedup**: 해시 기반 중복 결과 포인터 치환
- **Watchdog**: 장기 지연 및 루프 감지 엔진
- **내장 엔진 버전 · 업스트림 확인**: 지금 도는 원본 엔진의 커밋과 버전, 업스트림 브랜치 헤드와의 거리, 최신 릴리즈, 변경 파일 수를 확인
- **사이드콜 모델 슬롯**: Micro-skills 제안기와 Loop Guard 판정기가 사용할 모델을 각각 지정 (비용 절감)

> **Tiering · Dedup · Watchdog 은 서브에이전트 세션에서도 동작한다** (2026-11-14 게이트 수정).
> 엔진 경로(훅 · export · fold · ledger)만 루트 전용이다. 스위치: `subagentMemory` (기본 `true`).
> 근거는 [ARCHITECTURE.md](ARCHITECTURE.md) §3.1.

## 2. 두 개의 버전, 서로 다른 것

| 표시 | 값 | 무엇의 버전인가 |
|---|---|---|
| **플러그인 버전** | `0.0.1-rc.8` | 이 패키지의 버전. 숫자 부분(`0.0.1`)은 소유자, `rc.<n>`은 이 트랙의 이력 표식 |
| **내장 원본 엔진 버전 (업스트림)** | `v0.1.0+22.g6141bb9` | `microsoft/TokenEconomizer` 의 릴리즈 라인. 이 플러그인이 올리는 버전이 아니다 |

원본 엔진은 **버전 문자열 자체가 없다** (`__version__` 없음, `VERSION` 파일 없음, `te --version` 은
서브커맨드를 요구하므로 유효 호출이 아님). 그래서 엔진의 버전은 핀된 커밋의 태그 이력에서
파생된다. 태그가 없는 체크아웃(필터 클론)에서는 `git describe` 가 실패하므로 짧은 커밋 id로
표시한다 (`unreleased+6141bb92`).

> **주의**: 업스트림 태그만 단독으로 보여주면 "이 플러그인이 v0.1.0이다"로 읽힌다. 그 태그는
> `microsoft/TokenEconomizer` 의 것이고, 이 플러그인의 릴리즈 라인은 `0.0.1-rc.N` 이다.

## 3. 사이드콜 모델 슬롯

Micro-skills 제안기와 Loop Guard 판정기는 세션마다 LLM 을 한 번씩 호출한다. 각각 사용할
모델을 지정할 수 있다.

| 슬롯 | 엔진 설정 키 | 쓰기 가능? |
|---|---|---|
| 기본 모델 / Default model | *(없음)* | **아니오** — 엔진에 해당 설정 키가 없다. 배포 환경 자체 경로이므로 **사실로만** 표시 |
| Micro-skills 제안기 모델 | `microskills_model` | 가능 |
| Loop Guard 판정기 모델 | `loopguard_model` | 가능 |

값은 **`provider/model`** 쌍 (`deepseek-account/deepseek-flash`). DSH 는 provider 로 라우팅하고
model id 는 그 안에 속하기 때문이다. 구분자 없는 문자열은 provider 를 지정하지 못하므로 경계에서
거부된다.

드롭다운 목록은 **호스트의 LLM 레지스트리**에서 나오므로, 이 배포가 실제로 라우팅할 수 있는
것만 나온다.
